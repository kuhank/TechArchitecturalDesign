FACILITY → CODE SET

CODE TABLES (STORAGE)

Pattern rules
  • One table per regulator + code type, e.g. ACCUMED_DHA_ICD10, ACCUMED_DHA_CPT, ACCUMED_DHA_HCPCS, ACCUMED_HAAD_CPTS.
  • One row per code. The code years it belongs to = bit columns [2012] [2018] [2021] …
  • New code year = schema change: ALTER TABLE ADD [YYYY] on every table + view change.
  • No FKs: tables are joined only inside the view.

VIEW (FILTER) → UI

How the UI picks codes
  1. Facility → its code set (ACCUMED_CODE_SET_VERSION, e.g. 2 = DHA).
  2. View section for that code set filters code rows by year flag + row dates.
  3. App keeps rows where the encounter date is between effective_date and EXPIRY_DATE (ICD: end date · activity codes: start date).

Pattern rules
  • Same 3 tables for every code type: <x>_code, <x>_version, <x>_code_version.
  • A code row is shared by all its years; the link table says which years.
  • New code year = data only: +1 version row, new codes, links, a regulator_codebase row. No schema change.
  • App: regulator + encounter date → regulator_codebase row → version ids → allowed codes via links.

Legacy – codes a facility can pickSQL SERVER · ACCUMED
-- ICD codes valid for facility MF2195 on 05-Jan-2027
SELECT CODE, DESCRIPTION, effective_date, EXPIRY_DATE
FROM dbo.CODE_DESCRIPTION_VERSIONED
WHERE FACILITY_LICENSE = 'MF2195'
  AND type = 0                                   -- 0 ICD · 3 CPT · 4 HCPCS
  AND '2027-01-05' BETWEEN effective_date AND EXPIRY_DATE;
Add a new code year – legacy
  1. Back up code tables + script the view.
  2. ALTER TABLE … ADD [YYYY] bit on each code table.
  3. Flag codes in the new file; insert new codes with the new start date.
  4. View: add OR ([YYYY]=1 AND start >= cut-over) in that regulator's section; end discontinued codes the day before.
  5. Test the UI list before / after the cut-over date.
Unified Billing – codes valid for a claimPOSTGRES · BILLING
-- ICD codes valid for DHA on encounter end date 05-Jan-2027
SELECT c.code, c.short_description
FROM regulator_codebase rc
JOIN diagnosis_code_version cv ON cv.diagnosis_version_id = rc.diagnosis_version_id
JOIN diagnosis_code c ON c.id = cv.diagnosis_code_id
                     AND c.regulator_id = rc.regulator_id
WHERE rc.regulator_id = '3835f537-1b2e-4069-b306-1295f8e7502d'  -- DHA
  AND DATE '2027-01-05' BETWEEN rc.start_date AND rc.end_date;
Add a new code year – UB
  1. +1 row in each <x>_version (version API).
  2. Upload the code file per regulator (code upload API): existing codes → link only, new codes → row + link.
  3. Close the current regulator_codebase row (end date) and add a new one from the cut-over date.
  4. Validate counts, orphan / duplicate links, sample claims.
